# 1. Purpose

This document explains how every request travels through the backend.

It is the most important learning document for understanding the architecture.

Every developer should understand this document before writing business logic.

↓

↓

Step 3

↓

↓

Step 5

DTO validation occurs.

↓

Step 6

Handler calls Service.

↓

Step 7

↓

Step 8

Repository queries database.

↓

↓

↓

↓

Step 12

# 6. Handler Layer

Responsibilities

- Parse request
- Validate DTO
- Call service
- Return HTTP response

Handlers should never:

- execute SQL
- perform business logic
- calculate wallet balances
- hash passwords

Example

```
POST /wallet/deposit

↓

WalletHandler.Deposit()
```

---

# 7. Service Layer

Services contain business logic.

Example

WalletService.Deposit()

Responsibilities

- Validate business rules
- Start database transaction
- Call repositories
- Publish events
- Return domain objects

Services know nothing about HTTP.

---

# 8. Repository Layer

Repositories communicate with PostgreSQL.

Responsibilities

- CRUD
- Filtering
- Pagination
- Transactions
- Query optimization

Repositories should not:

- send emails
- validate passwords
- verify JWTs

---

# 9. Database Layer

The database stores:

Users

Wallets

Transactions

Properties

Investments

Notifications

Documents

Audit Logs

Refresh Tokens

Repositories are the only layer allowed to communicate directly with PostgreSQL.

---

# 10. Response Construction

Responses follow one format.

```json
{
    "success": true,
    "message": "Wallet funded successfully.",
    "data": {}
}
```

Errors

```json
{
    "success": false,
    "message": "Insufficient wallet balance.",
    "errors": {
        "amount": [
            "Balance too low."
        ]
    }
}
```

# 19. Performance Considerations

- Minimize database round trips.
- Avoid N+1 queries.
- Reuse connections.
- Batch writes where possible.
- Use pagination.
- Index common filters.
- Publish long-running tasks asynchronously.

---

# 20. Common Mistakes

Avoid:

- SQL inside handlers.
- Business logic inside repositories.
- Returning GORM models directly.
- Multiple response formats.
- Ignoring context cancellation.
- Long-running work inside HTTP handlers.
- Database access from middleware.
- Circular dependencies.

Every request should follow the same predictable path through the system.
