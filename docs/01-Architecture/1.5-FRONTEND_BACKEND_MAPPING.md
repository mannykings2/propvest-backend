# 1. Purpose

This document maps every frontend feature to its corresponding backend implementation.

It answers the following questions:

- Which backend endpoint powers this screen?
- Which database tables are involved?
- Which user roles can access it?
- What is the implementation status?
- What remains to be built?

This document is the primary coordination reference between frontend and backend development.

- Loading states should be consistent.

- Form validation should mirror backend validation rules.

# Conclusion

The frontend provides a strong foundation with most user interfaces in place, while the backend currently implements only a subset of the required functionality. The recommended approach is to prioritize completion of the authentication, wallet, property, and investment modules before expanding into administrative and analytics features. This sequence minimizes integration risk and enables the frontend to progressively transition from mock or partial data to fully functional production APIs.

This document should be reviewed and updated whenever new frontend screens, backend endpoints, or domain features are introduced to ensure both applications remain aligned.
