# Local Development Setup Guide

This guide explains how to run the PropVest backend locally for development.

## Architecture

For local development, we run:
- **Infrastructure** (Postgres, Redis, RabbitMQ): In Docker containers
- **API & Worker**: Directly on your machine using `go run`

This approach is faster for development since you can quickly restart the Go application without rebuilding Docker images.

## Quick Start

### 1. Start Infrastructure Services

```powershell
# Start only the infrastructure services (not api/worker)
podman compose up -d postgres redis rabbitmq
```

Wait a few seconds for services to become healthy, then verify:

```powershell
podman ps
```

You should see three healthy containers:
- `propvest_postgres` on port 5435
- `propvest_redis` on port 6379
- `propvest_rabbitmq` on ports 5672 and 15672

### 2. Run the API Locally

```powershell
make run
```

This automatically:
1. Copies `.env.local` to `.env` (which has `localhost` addresses)
2. Starts the API server with `go run ./cmd/api`

The API will be available at http://localhost:8081

### 3. Verify Everything is Working

```powershell
# Test the health endpoint
Invoke-WebRequest -Uri "http://localhost:8081/health" -UseBasicParsing
```

## Environment Files

- **`.env`**: Used by the application (auto-generated by Makefile from `.env.local`)
- **`.env.local`**: Local development config with `localhost` addresses
- **`.env.example`**: Template for new developers

**Important**: Never commit `.env` to git - it's in `.gitignore`

## Stopping Services

```powershell
# Stop the Go API (Ctrl+C in the terminal where it's running)

# Stop infrastructure containers
podman compose stop postgres redis rabbitmq

# Or stop everything including volumes
podman compose down -v
```

## Troubleshooting

### Error: "lookup postgres: no such host"

This means the API is trying to use Docker hostnames. Solution:
```powershell
# Ensure .env.local exists and has localhost addresses
# Then run:
make run
```

### Error: "Dirty database version"

This happens when migrations are interrupted. Solution:
```powershell
# Force the migration to the last known good version (e.g., 16)
migrate -path internal/database/migrations -database "postgres://propvest:password@localhost:5435/propvest?sslmode=disable" force 16

# Then run migrations
make migrate-up
```

### Podman Machine Issues

If you see errors like "input/output error" or "seccomp.json":
```powershell
# Restart the Podman machine
podman machine stop
podman machine start
```

### Port Already in Use

If port 8081 is already in use:
```powershell
# Find what's using the port
netstat -ano | findstr :8081

# Kill the process (replace <PID> with the actual process ID)
taskkill /PID <PID> /F
```

## Running with Docker (Alternative)

If you prefer to run everything in Docker:

```powershell
# This runs api and worker in containers too
podman compose up -d
```

Note: You'll need to rebuild the Docker image after code changes:
```powershell
podman compose up -d --build
```

## Useful Commands

```powershell
# View API logs (when running locally)
# Just check the terminal where you ran `make run`

# View infrastructure logs
podman logs propvest_postgres
podman logs propvest_redis
podman logs propvest_rabbitmq

# Access database directly
podman exec -it propvest_postgres psql -U propvest -d propvest

# Check migration status
make migrate-version

# Run migrations
make migrate-up

# Rollback last migration
make migrate-down
```

## Database Management

### Reset Database (Development Only)

```powershell
# Terminate connections and drop database
podman exec propvest_postgres psql -U propvest -d postgres -c "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='propvest' AND pid != pg_backend_pid();"
podman exec propvest_postgres psql -U propvest -d postgres -c "DROP DATABASE propvest;"
podman exec propvest_postgres psql -U propvest -d postgres -c "CREATE DATABASE propvest;"

# Run migrations
make migrate-up
```

## Frontend Integration

The frontend (Vite on port 3000) proxies `/api/*` requests to `http://localhost:8081`.

Make sure:
1. Infrastructure containers are running
2. API is running locally (`make run`)
3. Frontend dev server is running (`npm run dev` in propvest-app)

Then the frontend will successfully connect to the backend.
